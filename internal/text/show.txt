⏺ encoder.go 整体用途

  这个文件实现了一个可逆的 uint64 ↔ 13字符字符串编解码器，核心思想是"密码本（book cipher）"——用一张随机排列的字符映射表把数字变成看似随机的字符串，且这个过程是确定性可逆的。

  ---
  数据结构

  encoder.table[73][72]byte

  想象一张 73 行 × 72 列的字符表：

  行 0  : ['x', 'Q', '3', '@', ...]  ← 72个字符的某种随机排列
  行 1  : ['m', 'Z', '!', 'a', ...]  ← 另一种随机排列
  ...
  行 71 : ['@', 'b', 'Y', '7', ...]
  行 72 : ['k', 'p', 'W', ...]       ← 特殊的"索引行"

  前 72 行（行 0–71）：每行都是同一个字符集的不同随机排列，充当"密码本"。
  第 72 行：是"行号查找表"，把行号本身编码成一个字符。

  encoder.inverse[73][256]int8 是上面表格的反查表，给定字符找到它在某行中的位置（用于解码）。

  ---
  函数逐一解释

  build(cfg) — 构建密码本

  seed := fnv.New64a(cfg.TimeSeed).Sum64()
  rng := rand.NewPCG(seed, seed ^ PCGStreamSeed)

  用配置里的 TimeSeed 字符串做哈希，得到一个 64 位整数作为随机数种子。然后用 PCG 算法（一种高质量伪随机数生成器）初始化随机源。

  for i := range e.table {
      copy(e.table[i][:], cfg.CharacterSet)  // 先复制原始字符集
      // Fisher-Yates 洗牌
      for j := bookLen-1; j > 0; j-- {
          k := rng.IntN(j+1)
          swap(e.table[i][j], e.table[i][k])
      }
  }

  对每一行用 Fisher-Yates 洗牌算法做随机排列。因为随机数序列是确定的（固定种子），所以每次启动生成的表格完全相同——这是可逆解码的前提。

  本质：把字符集 "abc...Z01...()"（72个字符）打乱 73 次，得到 73 张不同的"密码表"。

  ---
  rowOf(val) — 根据值决定用哪一行

  func rowOf(val uint64) int {
      h := val
      h ^= h >> 33
      h *= MurmurHash3Mix1   // 0xff51afd7ed558ccd
      h ^= h >> 33
      h *= MurmurHash3Mix2   // 0xc4ceb9fe1a85ec53
      h ^= h >> 33
      return int(h % 72)
  }

  这是 MurmurHash3 的 fmix64 终结函数，专门设计用于把一个整数"充分打散"（雪崩效应：输入改变1位，输出平均改变32位）。

  作用：给定任意 uint64，确定性地映射到 0–71 之间的一个行号。不同的值会被分配到不同的行，让编码结果更难猜测。

  ---
  encode(val) — 编码：uint64 → 13字符

  第一步：base-72 分解（类似十进制转换，但基数是 72）

  for i := dataDigits-1; i >= 0; i-- {
      digits[i] = byte(v % 72)
      v /= 72
  }

  把一个 uint64 拆成 11 位 base-72 数字（72¹¹ ≈ 10²⁰，足以覆盖 uint64 的全部范围 2⁶⁴ ≈ 1.8×10¹⁹）。

  第二步：计算校验位

  chk = (d0 XOR d1 XOR ... XOR d10) % 72

  把 11 个数字全部异或，结果作为第 12 个数字（校验位），解码时可以验证数据完整性。

  第三步：用密码表映射

  encoded[i] = e.table[row][digits[i]]

  每个数字（0–71 的整数）通过选定行的密码表，变成一个真实的可打印字符。

  第四步：插入"行号字符"

  indexChar := e.table[72][row]  // 行号本身也编码成字符
  pos := row % 13                // 插入位置

  解码时需要知道用了哪一行，但不能明文存储行号，所以把行号也用第 72 行的密码表编码成一个字符，插入到字符串的第 row % 13 个位置。

  最终输出：11个数据字符 + 1个校验字符 + 1个行号字符 = 13个字符。

  ---
  decode(s) — 解码：13字符 → uint64

  因为不知道用了哪一行，只能暴力枚举 72 行：

  for r := range 72 {
      pos := r % 13
      if bs[pos] != e.table[72][r] {  // 检查该位置的字符是否与行号字符匹配
          continue
      }
      if val, err := e.tryRow(bs, r, pos); err == nil {
          return val, nil
      }
  }

  对每个候选行号 r，先用第 72 行的密码表检查行号字符是否吻合，再调用 tryRow 做完整验证。

  ---
  tryRow(bs, row, indexPos) — 尝试某一行解码

  1. 从 13 个字符中剔除行号字符，剩下 12 个（11数据 + 1校验）
  2. 用 inverse 反查表把字符转回 0–71 的数字
  3. 验证校验位：d0 XOR ... XOR d10 == chk（不符合说明这行是误判）
  4. 把 11 个 base-72 数字合并还原成 uint64
  5. 最终验证：rowOf(val) == row（如果这个值本来就不该用这行，则拒绝）

  ---
  整体流程图

  编码：
  uint64 (如 12345678)
    → base-72 分解 → [d0, d1, ..., d10]（11个数字）
    → 计算校验位 chk
    → rowOf(val) 确定行号 row
    → 用 table[row] 把每个数字映射成字符
    → 把 table[72][row] 插入第 row%13 位
    → 得到 13 字符字符串

  解码：
  13 字符字符串
    → 枚举 72 个行号 r
    → 检查 table[72][r] 是否在第 r%13 位
    → 剔除行号字符，用 inverse[r] 还原数字
    → 验证校验位
    → base-72 合并成 uint64
    → 验证 rowOf(result) == r
    → 返回 uint64

  安全性来源：密码表的随机排列依赖 TimeSeed，不知道种子就无法构建映射表，也就无法解码。即使知道算法，没有密钥（TimeSeed）也无从破解。
